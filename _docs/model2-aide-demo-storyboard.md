## 1. Model 2 — the definition (source for the slides)

> **Model 2** is Electric Mind's methodology for AI-assisted software delivery — a structured way of working in which **AI produces the documentation, traceability, and consistency that rigorous delivery requires, while humans direct, validate, and approve every step.** Spec-driven development is *how* Model 2 is implemented (increasingly through AI agents and skills); the methodology defines **what must be produced, who owns it, and what the organization is accountable for.**

**Five defining characteristics:**
1. **Human authority is explicit; gates are mandatory** — a stage advances only once the accountable person signs off; control is built into the method, not left to discipline under deadline.
2. **Enterprise governance lives in the delivery flow** — constraint manifests, audit-grade traceability, and accountability at each gate let AI-assisted delivery meet a regulated bank's audit, risk, and regulatory bar.
3. **It works at the scale of the whole organization** — adoptable bank-wide, across roles, teams, and governance layers — not one developer at a time.
4. **It defines what people's roles become** — maps today's roles toward a consolidated, AI-aligned set.
5. **Traceability is end-to-end and owned** — each artefact's contents, owner, and retention are specified, so a decision traces back to a business requirement and forward to the test that verifies it, in audit-ready form.

**Relationship to A.I.D.E.:** *"Model 2 is the method; A.I.D.E. is the system that makes it real."* A.I.D.E. (AI Integrated Delivery Enablement) is the skills-based SDLC framework, read directly by AI coding agents, that operationalizes spec-driven development across the full lifecycle.

**The demo shows 2 of the 5 characteristics on screen** — *(1) mandatory human gates* and *(5) end-to-end traceability.* The other three are organizational and are stated on the slides, not demonstrated.

## 3. Movie storyboard — what gets recorded

Notation: **[RT]** = real-time, **[FF]** = fast-forward/time-lapse. Pre-recorded (generation is slow and non-deterministic; recording guarantees the runtime and outcome). Fast-forward the "AI grinding"; stay real-time on the elicitation prompts and the review gates — *the gates are the clearest answer to "how is this not just fancier vibe coding?"*

### Act 1 — Reverse-engineer the Electric Wealth app → knowledge base *(~8 min)*
- **A1 · Orient [RT].** Show the `new-electric-wealth` monorepo (mobile / server / packages). Beat: "A real app. No docs loaded into the AI — we start from the code."
- **A2 · Analyze repository [RT→FF].** `/analyze-repository` classifies the codebase (monorepo, mobile + API). Beat: "A.I.D.E. first works out what kind of system it's looking at."
- **A3 · Reverse-engineer [FF].** Run the reverse-engineering skill(s) over the app. Pause **[RT]** on one elicitation prompt — A.I.D.E. asking rather than guessing. Beat: "It asks before it assumes."
- **A4 · Build knowledge base [FF].** `/build-knowledge-base`.
- **A5 · KB reveal [RT].** Open `ARCHITECTURE.md`, component files, `NAVIGATE.md`. Beat: "This is the system's understanding, written down — **the foundation we build the new feature on.**"

### Act 2 — Build the RRSP calculator on that foundation *(~14 min)*
- **B1 · The requirement [RT].** Show the RRSP calculator requirement (business + functional req, screen, API contract). Beat: "A concise, human-written requirement — the input to the pipeline."
- **B2 · Requirements package [FF gen → RT gate].** `/create-requirements-package` (brownfield; discovers current capability from the KB). Real-time on the review gate and on the terse requirement being elaborated into a full package.
- **B3 · Design package [FF gen → RT gate].** `/create-design-package`; the architecture-baseline step reads the KB. Real-time on the design review gate.
- **B4 · Implementation package [FF gen → RT gate].** `/create-implementation-package`; show the increment list (INC-XXX) and the GO/NO-GO gate.
- **B5 · Execute increments [FF gen → RT gate].** `/execute-increments`; real-time on an AI gate (tests pass) and a human gate (code review). Beat: "AI writes the code; engineers approve it against the spec."

### Close — the feature, working *(~3 min)*
- **C1 · Run it [RT].** Launch the RRSP calculator in the app; enter savings/contribution; see the projection and chart. Beat: "A real, working feature — built on the reverse-engineered foundation."
- **C2 · Trace it [RT].** Walk the line: running feature → increment → design decision → originating requirement, each with its approval gate. Beat: "Every line traces back to a requirement and forward to the gate that approved it — that's why this passes an audit."
