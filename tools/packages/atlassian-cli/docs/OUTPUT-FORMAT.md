# Atlassian CLI - Output Format Reference

The CLI caches raw API responses as JSON. No markdown is generated automatically — markdown analysis is authored by agents using the cached JSON as input.

---

## Cache File Structure

### Jira Issue

```
cache/jira/{PROJECT_KEY}/{ISSUE_KEY}/
├── {ISSUE_KEY}.json          ← Raw Jira API response (full issue object)
├── .meta.json                ← Cache metadata (timestamps, URLs)
└── {ISSUE_KEY}.analysis.md  ← Agent-generated analysis (populated on demand)
```

**Example:**
```
cache/jira/CEAJ/PROJ-123/
├── PROJ-123.json
├── .meta.json
└── PROJ-123.analysis.md
```

### Confluence Page

```
cache/confluence/{SPACE_KEY}/{PAGE_ID}-{title-slug}/
├── {PAGE_ID}.json            ← Raw Confluence API response (full page object)
├── .meta.json                ← Cache metadata (timestamps, URLs)
└── {PAGE_ID}.analysis.md    ← Agent-generated analysis (populated on demand)
```

**Example:**
```
cache/confluence/CPBDST/3480549310-ceaj-3843-arrival-ready/
├── 3480549310.json
├── .meta.json
└── 3480549310.analysis.md
```

> **Note:** Output directory is configurable via `OUTPUT_DIR` in `.env`. Default is `cache/`.

## Meta File — `.meta.json`

Tracks cache state for smart refresh decisions.

```json
{
  "issueKey": "PROJ-123",
  "issueType": "Feature",
  "lastFetch": "2026-04-20T14:30:00.000Z",
  "updated": "2026-04-06T11:22:32.967-0400",
  "url": "https://jira.example.com/browse/PROJ-123",
  "title": "Arrival Ready (Pre-Arrival Digital Account Opening)",
  "status": "Refining",
  "project": "CEAJ",
  "version": "2"
}
```

For Confluence pages:

```json
{
  "pageId": "3480549310",
  "title": "PROJ-123 Arrival Ready",
  "spaceKey": "CPBDST",
  "lastFetch": "2026-04-20T14:30:00.000Z",
  "updated": "2026-04-19T09:15:00.000Z",
  "url": "https://confluence.example.com/pages/3480549310",
  "version": "12"
}
```

## JSON Response — Jira Issue

The `.json` file contains the full Jira REST API v2 issue object. Key fields:

```json
{
  "key": "PROJ-123",
  "fields": {
    "summary": "Arrival Ready (Pre-Arrival Digital Account Opening)",
    "issuetype": { "name": "Feature" },
    "status": { "name": "Refining" },
    "priority": { "name": "High" },
    "assignee": { "displayName": "Wong, Sierra" },
    "reporter": { "displayName": "Kara, Muhammad" },
    "created": "2024-01-22T13:54:10.480-0500",
    "updated": "2026-04-06T11:22:32.967-0400",
    "labels": ["EA-TRANSFORM", "EAJ_Core"],
    "description": "...",
    "subtasks": [],
    "issuelinks": [],
    "customfield_14400": "...",
    "customfield_26905": "..."
  }
}
```

Custom field IDs are project-specific and listed in `src/field-mappings/{PROJECT}/fields.json`.

## JSON Response — Confluence Page

The `.json` file contains the full Confluence REST API page object. Key fields:

```json

  "title": "PROJ-123 Arrival Ready",
  "type": "page",
  "space": { "key": "CPBDST", "name": "CPB Digital Solution Train" },

  "ancestors": [],
  "children": { "page": { "results": [] } },
  "_links": { "webui": "/pages/3480549310" }
}
```

## Analysis File — `*.analysis.md`

The `.analysis.md` file is **not generated by the CLI**. It is authored by agents using the cached JSON as source. Agents write their analysis here so it persists alongside the cache.

Example structure an agent might write:

```markdown
# PROJ-123 — Arrival Ready

## Summary
Feature for pre-arrival digital account opening for new-to-Canada customers.

## Key Requirements
- Eligibility rules for N2C applicants
- NAPS intercept flow for non-residents

## Dependencies
- [ ] CEAJYS-7031 — NAPS intercept page update
- [x] DIGSTART-6111 — API integration story

## Notes
Extracted 2026-04-20. See full JSON for custom fields.
```

## Cache Refresh Behaviour

The CLI checks remote timestamps before deciding to use cache:

```
1. Check if .meta.json exists
2. Fetch remote "updated" timestamp (lightweight call)
3. Compare with cached timestamp
   - If equal → use cache, skip full fetch
   - If different → fetch fresh, overwrite JSON
4. Remove any legacy .md artifact (pre-v2 files)
```

Force a fresh fetch regardless of cache state:

```bash
atl j issue PROJ-123 --fresh
atl c page 3480549310 --fresh
```

## Field Mappings

Project-specific custom field IDs are stored in:

```
src/field-mappings/{PROJECT_KEY}/fields.json
```

Example `CEAJ/fields.json`:

```json
{
  "customfield_14400": "Acceptance Criteria",
  "customfield_26905": "Feature Statement",
  "customfield_26903": "Feature Owner",
  "customfield_26904": "Feature Size",
  "customfield_27100": "Feature Type"
}
```

Field mappings are auto-generated on first fetch of an issue from that project.
