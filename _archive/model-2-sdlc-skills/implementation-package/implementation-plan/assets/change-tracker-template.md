# Change Tracker Template

Use this structure to record implementation package documentation changes made during planning or execution.

## Package Version Log

| Version | Date | Author | Summary |
|---------|------|--------|---------|
| 0.1 | YYYY-MM-DD | <name> | Initial draft |

## Version Diff Summary

| From | To | Artifacts Changed | Summary | Reason |
|------|----|-------------------|---------|--------|
| 0.1 | 0.2 | <artifact names> | <what changed> | <why it changed> |

## Change Entries

| Date | Artifact | Section | Change | Impact |
|------|----------|---------|--------|--------|
| YYYY-MM-DD | <artifact> | <section> | <description> | <downstream impact> |

## Notes

- Record implementation package planning artifacts by file name without extension.
- Record material changes to scope, sequencing, tests, prerequisites, or readiness decisions.
- Do not use this template for source code commits; the PR workflow owns commit history and PR descriptions.
