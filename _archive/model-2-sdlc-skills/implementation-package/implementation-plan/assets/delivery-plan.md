## Validation Checklist

- [ ] Every schema change has a corresponding migration with a defined file name
- [ ] Migration ordering respects schema dependencies and coexistence requirements
- [ ] Every migration has a rollback script with documented data impact
- [ ] Data backfills use batched strategies for large tables
- [ ] Zero-downtime techniques specified for breaking changes (if required)
- [ ] Delivery sliced into independently deployable phases
- [ ] No forward dependencies between phases
- [ ] Each phase deployable without breaking the system if the next phase never ships
- [ ] Phase sizing reasonable (no phase > ~20 changed files without justification)
- [ ] Inter-phase dependencies mapped with dependency graph
- [ ] Parallel development opportunities identified
- [ ] Every phase has a defined rollback strategy
- [ ] Data-destructive rollbacks flagged with mitigation options
- [ ] Every phase has at least one validation gate
- [ ] Monitoring gates have defined time windows
- [ ] Delivery plan aligns with architect's deployment strategy (Section 12)
- [ ] Delivery plan aligns with prerequisites plan (infrastructure available before first phase)
