# update-knowledge-base — Inputs & Outputs

## Inputs

| Input | Type | Required | Mode | Notes |
|---|---|---|---|---|
| Implementation increment(s) | object / list | Yes | `full` | Output of `execute-increments`. Each carries goal, plan, FR list, AI/Human gate state. |
| Git diff | unified diff or list of `(file, line-range, change-type)` | Yes | both | Must reflect MERGED state (not feature-branch local). |
| Merge commit SHA(s) | full 40-char SHA | Yes | both | One SHA per repo touched. Becomes new `last_verified_against_commit` for affected components. |
| Feature ID | string | Yes | both | Becomes `last_feature_id` on affected components. Source: original requirement / story / ticket ID. |
| Previous component manifest | implicit | Yes | both | Read from `<knowledge_base_path>/components/**/*.md` at start of step 1. |
| Test / spec files added | list of paths | No | `full` | Used in step 2 to refresh the verification_signal hint and component body. |
| `--scope` | enum | No | — | `full` (default; from `execute-increments`) or `catalog-only` (from `execute-quick-change`). |
| `--feature-link` | URL | No | both | Optional link to ticket; written into the component body's "Recent Activity" §. |
| `--actor` | string | No | both | Author for the change-tracker row. Defaults to `framework.user.toml` `[user] name`. |

## Outputs

| Output | Path | Mode | Generated by step |
|---|---|---|---|
| Updated component frontmatter (affected only) | `<knowledge_base_path>/components/<repo>/<id>.md` | both | 2 |
| Updated component bodies (affected only) | same files, body sections | `full` | 2 |
| New change-tracker row | `<knowledge_base_path>/change-tracker.md` (append) | both | 3 |
| New ADR (only if threshold crossed) | `<knowledge_base_path>/shared/adrs/ADR-NNNN-<slug>.md` | `full` | 4 |
| ADR status flip on superseded ADR | `<knowledge_base_path>/shared/adrs/ADR-MMMM-<existing>.md` | `full` | 4 (single-line edit only) |
| Incrementally updated `graph.json` | `<knowledge_base_path>/graph.json` | `full` | 5 |
| Capability Index slice in ARCHITECTURE.md | `<knowledge_base_path>/ARCHITECTURE.md` § 4 | `full`, conditional | 6 (only if any affected component's triggers changed) |
| Update report (returned to caller) | inline | both | 7 |

## Validation gate (step 7)

| Check | Acceptance |
|---|---|
| Schema conformance | Every modified component still passes `config/SCHEMAS.md` § 3.2 validation. |
| Symmetry | depends_on / consumed_by remain symmetric across the KB. |
| Graph integrity | No edge references a missing node. |
| Orphan check | No component lost its only `paths:` glob (i.e. no component became "pointing at no source"). |
| Change-tracker row | New row contains: date, feature ID, comma-separated component IDs, summary, actor. |
| ADR uniqueness | If an ADR was emitted, its number is the next sequential number; the file did not already exist. |
| Stale-stamp consistency | Every affected component's `last_verified_against_commit` matches the merge SHA passed in for its repo. |

## Refusal modes

| Condition | Response |
|---|---|
| Diff matches paths in >50% of components | Refuse. Recommend `build-knowledge-base --overwrite` instead. |
| Diff matches paths in 0 components | Warn. Either the change is purely tooling/infra (no KB update needed), or component `paths:` are out of date. Suggest running `detect-knowledge-base-drift --mode=full`. Skill still appends a change-tracker row marked `Components Touched: (none — see drift report)`. |
| Merge SHA not present in repo | Refuse. SHA must be reachable from the repo's HEAD or a recent merge. |
| Feature ID empty | Refuse. Even ad-hoc changes must carry an ID (use `MAINTENANCE-<date>` if no ticket exists). |
| ADR threshold crossed but `--scope=catalog-only` | Warn loudly: "An ADR threshold was crossed but `catalog-only` mode skips ADR emission. Re-run with `--scope=full` if architectural impact." Proceed without emitting the ADR. |
