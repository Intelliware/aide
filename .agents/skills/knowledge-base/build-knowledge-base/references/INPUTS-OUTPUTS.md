# build-knowledge-base — Inputs & Outputs

## Inputs

| Input | Source / Path | Required | Used by step | Notes |
|---|---|---|---|---|
| `project.toml` | `{project-root}/project.toml` | Yes | 01–08 | Reads `[project]`, `[project.paths]`, `[[project.repos]]`. |
| `knowledge_base_path` | `project.toml` `[project.paths]` | Yes | 01 | Must exist; must be empty or user confirms overwrite. |
| RE Part A docs | `<knowledge_base_path>/source-docs/<repo-slug>/part-a/**` | Yes | 03 | Internal docs — used to derive component bodies. |
| RE Part B docs | `<knowledge_base_path>/source-docs/<repo-slug>/part-b/**` | Yes | 03 | Public/consumer docs — used to derive `description`, `triggers`, `paths`. |
| `[[project.repos]]` array | `project.toml` | Yes | 02 | Drives `repos/<slug>/` scaffold. Each entry's `code`, `name`, `path`, `role`, `type`, `primary` are read. |
| Latest commit SHA per repo | `git rev-parse HEAD` in each repo's `path` | Yes | 03, 06 | Populates `last_verified_against_commit` (full 40-char SHA) and `repository_map_table` Last Indexed Commit column. |
| KB block templates | `templates/blocks/knowledge-base/{architecture-index,repo-summary,component,shared-entity,adr-template,capability-index}.md` | Yes | 02–07 | Source of all rendered output structure. |
| `kb-instance-root` composition | `templates/compositions/kb-instance-root.yaml` | Yes | 06 | Drives ARCHITECTURE.md (architecture-index + capability-index blocks). |
| `kb-component` composition | `templates/compositions/kb-component.yaml` | Yes | 03 | Drives one `components/<repo>/<id>.md` per logical component. |
| Glossary references | `project.toml` `[project.glossary]` | No | 02 | Inlined into `<knowledge_base_path>/glossary.md`. |
| Cross-cutting pointers | RE Part B "standards" sections | Yes | 04, 06 | Auth, logging, error handling, etc. — pointers, not contents. |

## Validation gate (step 8 output)

| Check | Acceptance criterion |
|---|---|
| Coverage — endpoints | Every endpoint in any repo's RE Part B OpenAPI/spec maps to ≥1 component's `paths:`. |
| Coverage — exported framework symbols | Every exported symbol in any framework repo's RE Part B maps to ≥1 component. |
| Coverage — application entry-points | Every app entry-point in any UI/mobile RE Part B maps to ≥1 component. |
| Frontmatter — descriptions | Every component description starts with `Use when ` (case-sensitive). |
| Frontmatter — SHAs | Every `last_verified_against_commit` is a full 40-char SHA. |
| Graph integrity | No `depends_on` / `consumed_by` references a missing component_id. |
| Graph integrity | Node count in `graph.json` equals file count under `components/**/*.md`. |
| Repo references | Every component's `repo` field matches a `code` in `[[project.repos]]`. |
| Component IDs | Unique across the entire KB (not just within a repo). |
