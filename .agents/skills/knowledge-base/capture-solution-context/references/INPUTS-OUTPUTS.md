# capture-solution-context — Inputs & Outputs

## Inputs

| Input | Source / Path | Required | Used by step | Notes |
|---|---|---|---|---|
| `project.toml` | `{project-root}/project.toml` | Yes | 01–07 | `[project]`, `[project.paths]`, `[[project.repos]]`, `[project.glossary]`. |
| `knowledge_base_path` | `project.toml [project.paths]` | Yes | 01, 07 | Solution-context leaves write to `<KB>/shared/solution-context/`. |
| Existing solution-context leaves | `<KB>/shared/solution-context/*.md` | No | 01 | If present, Step 01 asks: refresh / replace / cancel. |
| Component catalog | `<KB>/components/<repo>/<id>.md` | No | 03, 04 | Used to link personas/KPIs to existing components by `component_id`. |
| ARCHITECTURE.md Capability Index | `<KB>/ARCHITECTURE.md` § 4 | No | 03 | Persona-to-capability matching. |
| RE Part A/B docs | `<KB>/source-docs/<repo>/**` | No | 02 | Auto-fills `00-overview.md` Classification (project type, languages, arch pattern). |
| `[project.glossary]` | `project.toml` | No | 07 | Existing entries preserved; new entries appended. |
| Elicitation patterns | `references/elicitation-patterns/{stakeholder-discovery,business-objectives,integration-discovery,non-functional-discovery,personas,ownership-and-raci}.md` | Yes (interactive mode) | 02–06 | Drives the user-facing conversation. |
| User identifier | `project.toml [project] user_email` or runtime prompt | Yes | 07 | Stamped on each leaf as `last_captured_by`. |
| `--non-interactive` flag | CLI / invocation arg | No | 02–06 | When set, elicitation is skipped and TODO stubs emitted. |
| `--refresh-only` flag | CLI / invocation arg | No | 01–07 | Re-elicits only the leaves whose `last_captured` is older than the staleness threshold. |

## Outputs

| Output | Path | Generated by step | Notes |
|---|---|---|---|
| Mission & overview leaf | `<KB>/shared/solution-context/00-overview.md` | 02 | Required leaf — never skipped, never empty. |
| Personas & use cases leaf | `<KB>/shared/solution-context/10-personas-and-use-cases.md` | 03 | Required leaf. |
| Goals & KPIs leaf | `<KB>/shared/solution-context/20-goals-and-kpis.md` | 04 | Required leaf; KPIs may be `TODO(baseline)` if no measurement system exists yet. |
| Constraints & compliance leaf | `<KB>/shared/solution-context/30-constraints-and-compliance.md` | 05 | Required leaf; "none" is a valid answer but must be explicit. |
| External integrations leaf | `<KB>/shared/solution-context/40-external-integrations.md` | 06 | Required leaf. |
| Ownership & RACI leaf | `<KB>/shared/solution-context/50-ownership-and-raci.md` | 06 | Required leaf. |
| Glossary delta | appended to `<KB>/glossary.md` | 07 | Existing entries preserved; new entries appended with date marker. |

## Validation gate (step 07 output)

| Check | Acceptance criterion |
|---|---|
| Frontmatter — descriptions | Every leaf's `description` starts with `Use when ` (case-sensitive). |
| Frontmatter — solution_context_id | Unique within `<KB>/shared/solution-context/`; matches the file's leading numeric prefix slug. |
| Frontmatter — last_captured | ISO-8601 date present on every leaf. |
| Required leaves | All six leaves exist (00, 10, 20, 30, 40, 50). |
| Component links | Every `related_components` entry resolves to an existing `component_id` in `graph.json`, or is omitted. |
| TODOs in non-interactive mode | Every TODO marker carries the original discovery question as a comment for the human follow-up. |
| Glossary delta | New entries appended; no existing entry deleted; date marker present. |
| Ownership leaf | RACI row exists for at least one team / role. |
