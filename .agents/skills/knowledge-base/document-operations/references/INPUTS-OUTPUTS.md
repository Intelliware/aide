## Frontmatter shape (every leaf)

```yaml
---
operations_id: <kebab-id matching numeric-prefix slug>
description: >-
  Use when {{the leaf's specific operational topic applies}}
triggers:
  - <keyword 1>
  - <keyword 2>
last_captured: <ISO-8601 date>
last_captured_by: <user_id>
---
```

## Validation gate (Step 03 output)

| Check | Acceptance criterion |
|---|---|
| Required leaves | All four leaves exist (00, 10, 20, 30). |
| Frontmatter — descriptions | Every leaf's `description` starts with `Use when `. |
| Secrets discipline | No leaf contains a string matching common secret patterns (regex sweep for `BEGIN PRIVATE KEY`, `aws_secret_access_key`, `postgres://[^@]+:[^@]+@`, …). Step 03 fails if any match. |
| SLO sanity | If `30-constraints-and-compliance.md` declares an uptime/latency SLA, `20-slos-and-monitoring.md` must contain a matching SLO row OR explicitly mark it `aspirational` with TODO. |
| On-call cross-ref | `30-runbooks-and-oncall.md` references the rotations from `50-ownership-and-raci.md` § 3. |
| Aspirational tagging | Every metric not currently measured is tagged `aspirational` with a responsible team. |
| Runbook size | Each runbook fits in ≤ 80 lines (warn) / ≤ 150 lines (fail). Larger runbooks are split. |
